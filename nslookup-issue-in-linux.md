# DNS Lookup Issue Troubleshooting SOP

## **Issue Identification**
When you encounter:
```bash
[root@centosdomain mysql]# nslookup google.com
;; connection timed out; no servers could be reached
```

## Verify Network Connectivity

**Check if basic network connectivity exists:**

```bash
ping 8.8.8.8
```

**Expected Output:**
```
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=112 time=22.4 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=112 time=22.6 ms
^C
--- 8.8.8.8 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss
```

**Diagnosis:**
- ✅ If `ping 8.8.8.8` works → Network is fine, **DNS-specific issue**
- ❌ If `ping 8.8.8.8` fails → Network connectivity issue (fix network first)

## Check Current DNS Configuration

**Run**

```bash
cat /etc/resolv.conf
```

**Example Output:**
```text
# Generated by NetworkManager
nameserver 192.168.19.2
nameserver 192.168.19.3
```

**Common Issues:**
- DNS servers are unreachable
- DNS servers are down
- Wrong DNS server IPs configured


**Check we can reach the DNS service or not:**
  ```
  nc -zv 192.168.19.2 53
  nc -zv 192.168.19.3 53
  ```
**Output should be:**
  ```
  # Ncat: Connected to 192.168.19.2:53
  or
  # Ncat: Connected to 192.168.19.3:53
  ```
>Connected is good. if not connected then this is the issue.

## Quick Temporary Fix

To Resolve DNS issue setup Google dns.

### Method A: Direct Edit (Temporary - lasts until reboot)

```bash
# Backup current config
cp /etc/resolv.conf /etc/resolv.conf.backup

```bash
# Edit the file
vim /etc/resolv.conf

# Add:
nameserver 8.8.8.8
nameserver 1.1.1.1

# Test immediately
nslookup google.com
```

### Method B: Make it Immutable (Prevent overwrite)
```bash
# After adding DNS servers
chattr +i /etc/resolv.conf

# To revert if needed
chattr -i /etc/resolv.conf
```

## Permanent Fix via NetworkManager

### Find connection name:

Run:

```bash
nmcli con show
```

Example Output:
```
NAME     UUID                                  TYPE      DEVICE
ens34    8af26ee6-7765-320b-a1f8-17008ca32e35  ethernet  ens34
```

### Set DNS servers:

```bash
# Replace "ens34" with your connection name
nmcli con mod "ens34" ipv4.dns "8.8.8.8 1.1.1.1"

# Restart connection
nmcli con down "ens34"
&
nmcli con up "ens34"

# Verify changes
cat /etc/resolv.conf
```

### Alternative: Use DHCP DNS

```bash
# Enable automatic DNS from DHCP
nmcli con mod "ens34" ipv4.ignore-auto-dns no
nmcli con mod "ens34" ipv4.dns ""
nmcli con down "ens34" && nmcli con up "ens34"
```

## Check Firewall Rules


**Check firewall status**

```bash
firewall-cmd --list-all
```
>See if dns service is blocked or not.


**Example:**

```text
public (active)
  target: default
  icmp-block-inversion: no
  interfaces: ens34
  sources:
  services: cockpit dhcpv6-client ssh
  ports:
  protocols:
  forward: yes
  masquerade: no
  forward-ports:
  source-ports:
  icmp-blocks:
  rich rules:
```
> Nothing is blocking here. Looks good.


**Allow DNS if needed or blocked**

```bash
firewall-cmd --add-service=dns --permanent
firewall-cmd --reload
```

**Note:** DNS uses port 53 (TCP and UDP)

## Verification Checklist

- [ ] Network connectivity verified (ping 8.8.8.8 works)
- [ ] Interface is UP with valid IP
- [ ] NetworkManager is running
- [ ] DNS servers configured correctly
- [ ] Firewall allows DNS (port 53)
- [ ] DNS resolution works (nslookup google.com)
- [ ] Changes are persistent after reboot


---

## Root Causes Summary

| Symptom | Likely Cause | Solution |
|---------|--------------|----------|
| ping 8.8.8.8 works, DNS fails | Wrong/Unreachable DNS servers | Change DNS to 8.8.8.8 |
| ping 8.8.8.8 fails | Network down | Fix network connectivity |
| resolv.conf keeps resetting | NetworkManager overriding | Use nmcli to set DNS |
| Firewall blocks DNS | Port 53 blocked | Allow DNS in firewall |
| SELinux blocking | SELinux policy | Check audit logs, disable temporarily |
